# REFACTORING.md — PLANET 前端重构标尺

> 重构时**改什么、怎么改、按什么节奏**。分工:
> - [`CLAUDE.md`](CLAUDE.md):决策透镜 + 硬约定 + 反向不变量 —— "**能不能**这么写"。两条法则、技术栈、effect 纪律、工作流在那里。
> - **本篇**:把判据落成可执行的**重构镜头**(命名 / 派生态 / 边界吞空 / 作用域卫生 / 卫语句 / 就近组织 / 节奏)。
>
> 本篇**只写镜头、只宏观、不绑具体实现**(例子随演化变动,活在代码 / git 里)。

---

## 0. 总则

- **精修 ≠ 重写**:外科级、可逆、**在源头改对**,不在错的设计上叠补丁(呼应 CLAUDE.md 两条法则:不留债、必治本)。
- 参考业界**只取思想、不作命名锚**。唯一允许背的"债"是"设计还没想清楚";绝不允许"明知更好却为省事不改"。

## 1. 命名 —— 名字必须和"它装什么 / 它做什么"一致

- **类型 / 接口名 == 它真正承载的东西**;名在撒谎就改名,不靠注释打补丁。
- **mapper / provider 方法名 == 它取的领域对象**:`playlistDetail` / `toplists` / `search`,不照搬上游接口名(`getSongListDetail` 留在 provider 实现内部,不外泄到 UI)。
- **组件 / hook / store-action / 事件 handler 名 == 行为**:`onX` 真的在 X 时触发,`useXxx` 反映它读 / 做的事。
- 消除 stutter;**文件名描述内容**,禁把 `utils.ts` / `index.ts` 当杂物堆。同目录改名不动公开面,低风险。

## 2. 注释

- 只解释 **why**;删 what-注释、过期注释、误导性"为什么"。
- 改名 / 重构后**同步清理所有引用**(doc-comment、import、示例),不留陈旧指向。

## 3. 值语义 / 引用稳定 / 不存派生态

- **不存派生状态**:凡能由 store / props / query 算出来的(如 `upNext` 由 `tracks`+`current` 派生),不再存一份 —— 走 selector / `useMemo` / 渲染期计算。存了就"改一处连改 N 处"且天然不同步。
- **引用稳定**:进 effect / `useMemo` deps、传给子组件的 object / array / function 要稳定身份;每帧新建 = 反复触发 + 白做 memo。
- **可选 vs 必填要诚实**:缺失用 `field?: T` / `T | undefined`,别拿 sentinel(`-1` / `""` / `{}`)假装"没有"。

## 4. 让边界自己吞掉"空 / 加载 / undefined"

数据可能未就绪时,**由提供它的 hook / 组件自己**给安全默认,消费者直接用:

- provider 不支持的能力返回**空数组 / 占位**(不抛错),调用方无脑 `.map`(已是 IProvider 约定)。
- 屏幕的 Hero **立即渲染骨架**(尺寸/位置定死),数据(<1s)到了再填 —— 这是 morph 能量到目标矩形的前提,**不要把整屏 gate 在 `isLoading` 后面**。
- 封面统一"有真图用 `<img>`,无则 seed 渐变"兜底,消费端不判空。
- 只在**真正会缺失**的边界加这层;内部已确定非空处再判空是噪音。

## 5. 作用域卫生 —— helper 与所有者就近

- 只被一个屏幕用的 helper:就近放它旁边(模块私有,不进 barrel)。
- 与某领域对象强相关的纯函数(QQ 字段映射)放进对应 `mappers/`,不散落到通用 util。
- **共享面越小越好**:`vibe/core.tsx`、`adapt.ts`、`hooks.ts` 只导出真正跨屏复用的符号。

## 6. 卫语句 / 降低分支复杂度

- 早返代替嵌套 `if`;查表 `Record<K,V>` 代替 3+ 条件链 / 嵌套三元。
- **JSX 里**:loading / empty 早返,别在一个 `return` 里堆三层三元;分支一多抽子组件让主体扁平(Search 的 空/loading/结果 三态就该这么分)。
- 但 `Shell` 的切换相位机(`trans` start→morph→reveal)那种**事件驱动的结构性嵌套**不是逻辑复杂度,别为"看起来浅"硬平铺。

## 7. 现代 JS / TS —— 判据照 CLAUDE.md §3

现代特性**只在"可读性 / 正确性↑ 且 不引入分配 / 不退化热路径"时采用**。**地道 ≠ 最新。**

## 8. 就近原则 / 组织 —— 相关放一起、公共下沉、按职责拆

- **相关代码放一起**(provider 实现 + 它的 mapper 同 feature);**公共下沉**到 `core` / `adapt`,不让多屏各抄一份。
- **god-file 按职责拆成同目录多文件**(纯移动,公开面不变);**大但内聚、单一职责的不拆**(`Shell.tsx` 的切换引擎是一体的,别为行数硬拆断它)。
- 拆完用 barrel / `index` 作目录唯一公开面,消费方零改动。

## 9. 工程硬规则(补 CLAUDE.md §4 之外)

- **工厂 / 构造类函数返回"有效值或抛错"**,不返回半成品(mapper 要么给出完整领域对象,要么给安全空值;别让屏幕拿到缺字段对象自己补)。
- **死代码立刻删**(改了取数路径就删掉不再用的旧 mapper / 旧 endpoint,如已下线的 `getSearchByKey`),不留"将来可能用"。
- 重构途中发现的**真实 bug 顺手修,但单独成 commit**。
- **边界校验(外部 wire / 用户输入)该校验就校验,内部数据流不加噪音**。

## 10. 节奏与纪律 —— 详见 CLAUDE.md §3 + §6

- **破坏性改动先算"爆炸半径"**:改 `MusicProvider` 形状 / store schema / vibe 屏幕 props 前,先 grep 所有消费方(跨 provider、跨屏、跨 hook),列影响面再动。
- **承认审计误报**:深入看后发现某"坏味道"其实是有意设计(切换引擎的结构性嵌套、内核/UI 的单向边界、内聚的大文件、无后端能力的屏幕走诚实空态),就 skip 并写明理由 —— 正常 false positive,别为"清干净"去动 morph 引擎这类正确性敏感处。

## 一句话

设计前问"**该不该**"(CLAUDE.md);重构时对照本篇镜头定"**改什么、怎么改**";每批一个可独立 revert 的 commit、`yarn typecheck && yarn build && yarn test` 全绿再推。**镜头是工程通则,例子活在代码里。**
